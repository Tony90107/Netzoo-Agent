# 精簡讀取：必填欄位與四類欄位規則 設計 spec

日期：2026-10-19　狀態：**使用者已同意（2026-10-19），待實作**
上層 spec：`2026-10-18-closed-menu-judgment-design.md`。本 spec 取代它的第 3.1 節（讀取形狀）與第 9.2 節（25 個欄位），並修改第 3.10 節（9/10 規則的適用範圍）。決策表的核心原則不變：模型只讀不判、程式判定、拒絕要有正面證據、意圖不替使用者猜。

## 0. 為什麼要改

兩組全新盲寫題的結果（h1、h2，各 48 題，事前凍結計分）：

| | 現行系統 | 封閉清單（最佳一組） |
|---|---|---|
| h1 嚴格分數 | 37/48 | 33/48 |
| h2 嚴格分數 | 38/48 | 31/48（先給選項） |

逐題歸因都指向同一處：**模型把句子拆進欄位時讀錯**。決策規則本身沒有問題：讀取正確時是 56/56，把正確的「要什麼」欄位換回去就從 74 升到 101/112。

讀錯的結構性原因（第 1 階段 56 題 × 2 次讀取的實測）：

- **一次要寫的值太多**：每題中位數寫 208 個值（最多 386），**真正有內容的只有 26 個**，其餘約 87% 是「沒說」「沒提」之類的空格。原因是 strict schema 要求每格都出現，每格又帶 5 個子欄位。
- **空格會被填錯，直接造成誤判**：
  - C29 沒提重疊分組卻填了「要重疊分組」→ 誤拒（2 次讀取都錯）；
  - H32 時間序列被填成「動態模型」→ 拒絕；
  - 沒說資料單位卻自己填「bulk」49 次。
- **錯誤會累積**：一題約有 10 個會影響判定的值，每個 95% 讀對，全對的機率只有約 60%。
- **同一欄位讀兩次會衝突**：意圖聚焦確認讓同一個欄位讀兩次，兩次常不一致（一次「有說」、一次「沒提」），h1 從 33 掉到 28/48。

使用者 2026-10-19 的決定：

> 只需要留著需要的欄位即可，剩下的不用存在，只會徒增誤判的風險。使用者原文進來，模型解析，結合程式輔助判斷，填入該有對應的欄位；如果有模糊或是無法填入的就先詢問使用者確認，確認過後不行就無法執行並說明原因，如果可以執行那就繼續跑 workflow。必須決定哪些欄位是一定要填入的，這個沒填就不能繼續進行；有些欄位是輔助用的；有重複的相似的欄位，保留一個就好。我們主要是要讓結果科學化：不能有做不到的事說成能做到，能做到說成做不到，模糊也沒有追問使用者。

## 1. 目標

三個科學目標，也是驗收時主要量的三種錯：

1. **做不到的，不說成做得到**（誤承諾）
2. **做得到的，不說成做不到**（誤拒）
3. **模糊的，一定追問**（該問沒問）

設計目標：

- 每題只讀「必填」與「這題用得到」的欄位，從 208 個值降到約 15–30 個。
- **每個欄位只讀一次**，不出現兩次讀取互相衝突、需要仲裁的情況。
- 欄位沒填，只會導致「追問」，不會導致「拒絕」。

非目標：

- 不改 workflow 合約與 capability sheet 的內容。
- 不改 prompt 措辭來誘導模型行為（沿用既有禁令），只改 schema 形狀與程式規則。
- 中文不進驗收門檻。

## 2. 流程

```
使用者原文
 → 第 1 步：核心讀取（模型）── 只填 A 類必填，以及使用者「有提到」的 C、D 類項目，每項附原文
 → 第 2 步：程式依合約算出候選 workflow，找出這些候選需要的 B 類欄位
 → 第 3 步：聚焦讀取（模型）── 只回答程式指定的 B 類欄位，每格附原文或標「沒說」
 → 第 4 步：程式判定（第 4 節）
     ├─ A、B 有缺或不確定 → 追問（附選項，最多 3 輪）
     ├─ C 類任一成立，或違反合約 → 明確說無法執行＋原因（附合約原文）＋最接近、可以做的選項
     └─ 全部通過 → 執行前確認（列出 D 類資訊）→ 使用者同意 → 執行
 → 使用者回答後：回答直接填入對應欄位（不重讀原文），回到第 2 步
 → 3 輪後仍有必填欄位未確定 → 不執行，列出還缺什麼（不說成「做不到」）
```

模型與程式的分工：

| 模型（只報字面事實，每項附原文） | 程式（套規則，每次結果相同） |
|---|---|
| 這句是要交付的結果、目的、背景，還是問題 | 數原文裡點名的方法名稱（`workflows_in`） |
| 結果對到清單上的哪一個值 | 驗證每段引文逐字在原文中 |
| 提到哪些資料、數字、設定、清單外的要求 | 依合約算候選 workflow、決定要問哪些 B 類欄位 |
| 回答程式指定的 B 類欄位 | 套用「沒提就是沒要」「之後比較是目的」等規則 |
| | 執行時從檔案讀樣本數、特徵數 |
| | 判定、選項排序、回覆文字（不由模型撰寫） |

## 3. 欄位：四類

**共同規則**：沒提到的欄位**不寫**（不再逐格寫「沒說」）。schema 用「提到的事實」清單表示，每筆含欄位名、值、原文；值由程式對照該欄位的選單檢查，以避開 strict schema 的 enum 上限（第 1 階段 v7 的教訓）。不確定時，該筆列出「在哪幾個值之間」並附原文。

### A 類：必填（每題都讀；缺任何一項就不能往下）

| 欄位 | 值 | 誰填 | 說明 |
|---|---|---|---|
| **A1 要交付的結果**（每個要求一筆） | 清單上的 10 種結果之一／泛稱（network、regulation）／只說目的或主題／在方法之間選／清單外（轉 C1） | 模型，附原文 | 「只說目的」「泛稱」「在方法之間選」都要有原文作證，才算模糊（CLARIFY）；只標「不確定」而沒列出選項，不算模糊 |
| **A2 提到的方法** | 每個名字的角色：要跑的／要選的／只是背景；以及要求使用的未註冊方法（轉 C5） | 名字由程式數，角色由模型標 | 只是背景提到的方法不算點名 |
| **A3 提到的資料** | 每項：資料種類＋「有」或「沒有」；另有「只有這些」標記 | 模型，附原文 | 沒提的不寫，**沒提不等於沒有** |
| **A4 執行或詢問** | 要執行／只是詢問 | 模型，附原文 | — |

### B 類：條件必填（程式依候選 workflow 的合約決定問不問；問了就必須有答案）

| 欄位 | 值 | 什麼時候問 |
|---|---|---|
| **B1 規模** | 整體一個／每組一個／每個樣本一個 | 候選在不同規模上導向不同 workflow；「每組一個」只在使用者提到分組時出現 |
| **B2 調控因子** | TF／TF＋miRNA（target prior）／清單外（以 miRNA 表現量驅動、lncRNA、RBP…，轉 C） | PUMA 類與 PANDA 類都還是候選；完全沒提 miRNA 時直接當成只有 TF（附加項規則） |
| **B3 多層資料怎麼建模** | 整合成一個（哪兩層）／各層各一個／清單外（三層以上一起建模，轉 C） | 候選含多組學 workflow，而且使用者有兩層以上資料 |
| **B4 workflow 專屬條件** | 依合約：SAMBAR 體細胞或生殖細胞突變；DRAGON 類連續值、同一批樣本；CONDOR 調控網路或基因–基因網路；BONOBO 已 log 轉換、已中心化 | 該 workflow 是候選 |
| **B5 設定** | 只對到**候選 workflow 的 control** 與允許值 | 使用者有提到設定；描述資料或輸出位置的字句不算設定 |
| **B6 數量** | 樣本數、特徵數 | 只在候選有數量限制時才相關。執行時由程式從檔案讀取；使用者有說數字就先算；使用者說不確定（例如「5 或 9 個」）而且會改變判定時才問 |

B 類的「沒說」由第 3 步的聚焦讀取標出，判定時視為缺少，要追問（B6 例外，由檔案取得）。

### C 類：禁止條件（使用者有提才填，需原文；任一成立，受影響的 workflow 就不能執行）

| 欄位 | 例子 |
|---|---|
| **C1 清單外的結果** | filtered VCF、差異表現基因、pseudotime 排序 |
| **C2 清單外的主張** | 證明因果、訓練預測模型 |
| **C3 對外動作** | 寄給醫師、上傳資料庫、儀表板、每週自動重跑 |
| **C4 資料形式的特殊狀況** | single cell、二元值（對連續值 workflow）、動態模型、空間鄰近、重疊分組 |
| **C5 未註冊的方法或變體** | TIGER、LIONESS-OTTER、DESeq2 |
| **C6 明說沒有的必要資料** | 「沒有 motif」「只有表現量」（來自 A3） |
| **C7 合約寫明不支援的設定或數值** | OTTER 加 L1、lam = 1.5、只給 lambda1（來自 B5、B6 的合約檢查） |

C 類是「正面證據」：只有使用者的原文說了，才會成立。**沒提到的 C 類欄位不存在，也就不會被填錯**（取代第 1 階段每題都要寫 10 個條件的做法）。

### D 類：輔助（不決定能不能做；唯一例外見 D4）

| 欄位 | 例子 | 處理 |
|---|---|---|
| **D1 分組** | 「44 個 AD、44 個 control」 | 讓 B1 出現「每組一個」選項 |
| **D2 之後要比較**（目的） | 「so I can later compare responders …」 | 記為目的，用來排列選項；回覆說明比較是 NetZoo 之後的步驟 |
| **D3 signed 偏好** | 沒提活化或抑制 | 方法平手時兩種都列，說明差別讓使用者選 |
| **D4 額外的要求** | 「每條邊要有 p 值」 | 逐項對照合約，見第 4.3 節 |
| **D5 原始檔要前處理** | FASTQ、BAM | 說明要先在 NetZoo 外處理成表格；不代做、不編步驟 |
| **D6 對檔案的疑問** | 「不確定是哪一版匯出」 | 要執行：執行前由程式檢查檔案；只是詢問：問使用者 |

**升格規則**：使用者把 D 類項目當成必要條件時，它改屬 B 類（必須有答案）或 A1（成為要交付的結果）。例如「要做統計檢定比較兩組」、「一定要知道 TF 是活化還是抑制」。

### 合併與刪除（相對於上層 spec 第 9.2 節的 25 個欄位）

| 原本 | 改成 |
|---|---|
| 14 種資料逐一標「有／沒有／沒提」＋`data_absent`＋`only_data` | A3：只列提到的資料，每項標「有」或「沒有」，另有「只有這些」標記 |
| `sample_count`、`feature_count`、`single_feature_count` | B6：提到的數字清單，每個標它在數什麼 |
| `integration`＋`layers` | B3 |
| `claims`、`delivery`、清單外結果 | C1–C3：清單外要求清單，每項標種類並附原文 |
| `context_mentions`、點名角色、`unregistered_methods` | A2 |
| `regulators`＋`mirna_driver` | B2 |
| `data_unit`、`value_type`、`data_stage`、`time_model`、`spatial`、`group_membership` | C4（特殊狀況，有提才填）；`data_stage` 的原始檔改成 D5 |
| `samples_matched`、`input_network`、`mutation_origin` | B4（只在對應 workflow 是候選時才問） |
| `signed`、`compare`、`groups`、`requirements`、`unsure_files` | D3、D2、D1、D4、D6 |
| 每格 5 個子欄位（status、basis、value、values、quote） | 每筆只有值、原文；不確定時加上「在哪幾個值之間」。沒說就不寫這格 |
| 逐句類別、逐數字標籤 | 併入 A1（這句的角色）與 B6（數字） |

## 4. 判定規則

### 4.1 通過標準

| 類別 | 標準 | 對應的科學目標 |
|---|---|---|
| A、B | **100%**：每一項都要有（明說、可推斷，或使用者回答） | 缺一項就不知道該跑哪個 workflow，或跑出錯的東西（目標 1、3） |
| C | **任一成立 → 受影響的 workflow 不能執行** | 目標 1 |
| D4 額外的要求 | 逐項處理（第 4.3 節） | 目標 1、2 |
| 其他 D 類 | 不做通過判斷，只影響呈現與執行前確認 | — |

歷史依據：accept24 的 11 個誤承諾中，有 9 個是「其他都符合、只差一個條件」，所以 A、B、C 不使用比例。

### 4.2 結局

| 情況 | 結局 |
|---|---|
| A1 有證據顯示沒說要什麼結果（只說目的、只用泛稱、在方法之間選），而且資料還留下兩種以上不同結果 | **CLARIFY**：依資料列出結果選項，請使用者選；沒說資料就一起問 |
| A1 沒說結果，但資料只留下一種可能 | **CLARIFY**：仍要確認（一個選項的選項卡） |
| A、B 有項目缺少或不確定，而且不同答案會導向不同結局 | **ASK**：問那一項（附選項）；每輪最多 2 題，結果和疑問可以同一輪一起問 |
| C 類成立，或 B5、B6 違反合約 | **DECLINE**：明確寫 NetZoo 不能做、原因（附合約原文）、最接近且可以做的選項 |
| 部分要求可做、部分不可做 | **DO（部分）**：分項列出；不自動只跑可做的部分 |
| A、B 全部確定，C 沒有成立，D4 處理完 | **DO**：給選項卡（最多 3 個，依符合度排序）；只剩一個就推薦它；執行前列出 D 類資訊請使用者確認 |
| 讀取失敗 | **UNCHECKED**：如實說無法判斷 |
| 3 輪後 A、B 仍有缺 | 不執行，列出還缺什麼；不說成「做不到」 |

**欄位沒填，永遠不會導致 DECLINE。** 只有 C 類的正面證據，或違反合約，才會拒絕。

### 4.3 D4 額外要求的逐項處理

```
每個要求逐項對照候選 workflow 的合約（met／contradicted 必須附合約原文，程式逐字核對）
 ├─ 合約寫明符合 → 通過
 ├─ 合約寫明做不到 → 這個 workflow 不能用（等同 C7），附原文，給最接近、可以做的選項
 └─ 合約沒寫 → 問一次「這是必要條件嗎？」
      ├─ 是 → 明說「合約沒有寫，無法保證做到」，由使用者決定要不要照跑
      └─ 不是 → 拿掉，繼續
```

「符合你說的 X/Y 項」的比例只顯示在選項卡上，用來排列選項先後，**不決定能不能做**（取代上層 spec 第 3.10 節「≥ 9/10 才放行」的寫法）。

### 4.4 每個欄位只讀一次

- A、C、D 在第 1 步讀；B 只在第 3 步、只讀程式指定的欄位。
- 同一個欄位不會被讀兩次，所以不需要「兩次不一致怎麼辦」的仲裁規則。
- 使用者的回答直接填入對應欄位，標成「回答」，之後不再重讀原文去覆蓋它。

## 5. 回覆

沿用已實作的選項卡與英文回覆模板（`2721d970`），回覆文字由程式依判定產生，不由模型撰寫：

- **DECLINE**：開頭直接寫 NetZoo 不能做什麼、為什麼（合約原文），接著列最接近、可以做的選項。
- **ASK、CLARIFY**：問題附選項，加上「不確定，請建議」與「都不是（請說明）」，並留一列讓使用者自己填套件名稱。
- **DO**：選項卡（差在哪、適合什麼需求、符合你說的幾項、還要確認什麼），以及執行前確認：列出 D 類資訊和程式做的假設。

## 6. 驗收

| S3 新盲寫題 h3 | 新的盲寫者（沒看過 h1、h2、56 題與本設計）寫約 48 題，再由獨立審核者核對正解；計分在跑之前凍結（ROUND.md） | 現行系統與精簡讀取，在同一組題目上各跑一次 |
| S4 決定 | 依 S3 結果，由使用者決定是否往 shadow 與上線推進 | — |

h1、h2 與 56 題都已用過，只能用來除錯，不能再拿來調整或驗收。

### 6.2 S3 的指標與門檻（凍結於 ROUND.md）

主要指標，對應三個科學目標：

| 指標 | 定義 |
|---|---|
| 誤承諾 | 不該做的題被當成可執行（含部分承諾） |
| 誤拒 | 該做的題被拒絕 |
| 該問沒問 | 該追問或該釐清的題，直接執行或直接拒絕 |

另外量：
- 整體嚴格分數；
- 追問是否問到關鍵事實（盲標）；
- 每題寫出的值數；
- 空格誤填次數。

採用門檻：精簡讀取在**三種錯的次數都不多於現行系統**，而且整體嚴格分數不低於現行系統。任何一項沒過，就不採用，並逐題報告原因。

- S3：現行系統 48 個 session（nemotron 免費額度＋gpt-4o-mini 約 US$0.1），精簡讀取 48 次讀取（約 US$0.1）。

## 7. 風險

- **A1 的讀取仍是關鍵**：「要什麼結果」讀錯，後面全錯。精簡讀取減少了干擾，但這一格的準確度要在 S2 單獨量。
- **B 類由程式決定問不問**：如果程式從合約推得不完整，就會漏問。這個風險由第 0 階段的齊全性檢查（C1–C4）把關，S1 要更新成新欄位。
- **兩步讀取多一次呼叫**：延遲稍增；兩步可以只在第 2 步算出需要 B 類欄位時才呼叫。
- **門檻可能過不了**：兩輪新題都是現行系統較好。若 S3 仍不如現行系統，就停在這裡，只保留已證明有用的呈現方式（選項卡、「不能做」附原文）。
