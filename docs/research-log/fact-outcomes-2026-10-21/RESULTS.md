- 日期：2026-10-21
- 起點：`f4197b7c`（已推送）
- 費用：$0。只有離線重放，沒有呼叫模型，也沒有改產品程式。
- 計畫：`collab/ROUND-21-PLAN.md` 的 R21-B。

## 結論：不建議照原計畫實作 R21-B

| R21-B 的修改 | 量測 | 上限 |
|---|---|---|
| R1 放寬到「同一句」 | `r1_sentence.py`：1,060 份讀取全部重放，**0 份判斷改變** | 0 |
| R3 改由程式計算結果 | fact agent 被 R3 擋掉的提問，金標問一題的只有 C31 ×3 | 3 |
| 為 fact agent 保留預算 | 被預算擋下 24 份，其中金標問一題 12 份。其中 9 份已經由舊的 needs_fact 路徑問了，仍判錯的只有 M01、M36、C43 p4c | 3 |

### R1 放寬到同一句：沒有作用

- 被 R1 擋掉的提問共有數百個，幾乎都在金標能做或不能做的題，所以 R1 是主要的精確度防線。
- 放寬後只有 5 份決定多了一題，判斷都沒變：那些回合原本就在問，或由更前面的規則決定。
- C11 的提問放寬 R1 後，仍被 R2 擋下：提問的 workflow 不在候選中。

### R3 改由程式計算：只有 C31

- 改由程式計算，fact agent 的輸出 schema 要加上型別維度與兩個候選值。
- fact agent 每輪約跑 520 次（金標四類都有），改 schema 會影響全部；這個專案量過小模型的 schema 加欄位或變長會變差（Round 4、Logs 229–233）。
- 上限只有 3 份，代價與風險不成比例。

### 預算：上限 3 份，而且要重問才能量

- 被擋下的回合，整輪已用掉約 55–65k token。
- 要量保留預算的效果，必須對 24 份讀取重問 fact agent（約 US$0.03）。
- 上限 3 份，並且要確認 9 份金標能做的不會因此多問。

## 量測時看到的其他事

- **現行讀題形狀的回合**（p4b 之後、g4o、h1–h4，共 498 份有金標）**判對已達 88%。** 舊回合（p0–p3）只有 73%，許多錯誤是舊讀題形狀或 provider 失敗造成的。
- **C31 是錯最多的「問一題」題目：11 次讀取錯 8 次，分三條路徑：**
  - 判做 4 次：R3 擋掉，或舊回合沒有 fact agent；
  - 「無法確認（routing_failed）」4 次：原因是 `research_choices_unavailable`。這是研究比較類請求在沒有讀出假設時「保守失敗」，即使沒有任何呼叫失敗；
  - 回覆說「這次無法判斷」是誠實的，但不是使用者要的答案。
- **現行回合剩下錯得較多的類別（每類 6–7 份）：**
  - 請說清楚 → 給了結果（例如 C53「how genes are connected」）；
  - 問一題 → 無法確認（routing_failed）；
  - 問一題 → 請說清楚（goal_unclear）。
