# 封閉清單判定：第 0 階段結果（2026-10-18）

## 結論

- **門檻通過：56/56**（門檻 ≥ 52）。do 14/14、dont 13/13、ask 15/15、vague 14/14。
- **這個分數的意義很窄**：讀取是我依讀取規則手寫的，寫的時候知道 gold。它只證明一件事：**讀取正確時，決策表能做出正確的判斷**，也就是設計本身表達得出所有正確答案。它不是實際表現；實際表現要等第 1 階段由模型讀取。
- **比分數更有參考價值的是「漏讀一個欄位」檢查**：294 次單一欄位漏讀中，86% 判定不變，7% 變成追問（安全），6% 變成錯的判定（危險）。危險的 18 次全部落在兩類欄位：
  - **漏讀限制**：設定值、樣本數、特徵數、「只有某資料」。結果是誤承諾（C13、C18、C30、C33、C57）。
  - **漏讀「我不確定」**：條件、數量、設定的雙選疑問。結果是沒問就做（C20、C21、C31、C42、C45、C48、C50、C56）。
- 所以第 1 階段要專門量這兩類欄位的召回率。我建議加一次**只針對候選 workflow 限制的聚焦讀取**：候選確定後，列出該 workflow 的 controls 和限制，只問「請求有沒有提到這些、有沒有表示不確定」。

## 測試

- 新增 652 項，全部通過。完整測試套件：4,522 通過、51 略過。
- **不變式**（完整 2,496 種讀取組合，0 違反）：
  - 拒絕一定有正面理由；什麼都沒說的讀取從不被拒絕。
  - 給出的 workflow 一定產生被要求的結果。
  - 多個 workflow 一定是有選項說明的平手。
  - 問題的每個選項都導向不同結果。
  - 每條回答路徑都會結束。
- **刻意弄壞，確認測試會抓到**（改完已還原）：
  - 把「沒說 granularity」偷偷預設成整體一個 → 2 項失敗。
  - 把「沒對到」改成直接拒絕 → 2 項失敗。
  - 把方法平手清單拿掉 → C1 失敗。

## 寫 56 題讀取時發現、已修的設計缺口

| 缺口 | 題目 | 修法 |
|---|---|---|
| 使用者在兩個具體值之間不確定時，問題要用他自己的兩個選項 | C06、C11、C31、C39 | `_decides`：逐一代入每個值，結果不同才問，選項就是那幾個值 |
| CLARIFY 與 ASK 的界線 | C34、C36 | 結果沒說或只有泛稱 → CLARIFY；使用者點名兩個具體結果 → ASK（和 56 題的定義一致） |
| 使用者的要求應該縮小平手 | C50 | 達到 90% 門檻的 workflow 才留下 |
| 沒指定 workflow 的設定 | C17 | 對每個候選 workflow 都檢查 |
| 必須宣告的設定 | C50 | YAML `required_settings`（BONOBO 的 log_transformed、centered） |
| 對具名檔案內容的疑問 | C43、C44 | `unsure_files`：run 時由輸入檢查先確認（說明，不追問）；不是 run 才問 |
| 二元值也排除表現量類 workflow | C20 | `value_type` 套用到所有吃連續值的 workflow |

## 「漏讀一個欄位」檢查後修的兩點

| 問題 | 題目 | 修法 |
|---|---|---|
| 結果沒被點名、資料只剩一種可能時，直接做了 | C15、C26 | 使用者沒說要什麼結果時，即使只剩一個選項也要確認 |
| 漏讀 miRNA → 退回只做 TF | C25、C59 | 資料裡有 miRNA prior 或 miRNA 表現量，就算「有提到」，regulators 沒說時要問 |

修完後，危險判定從 24 次降到 18 次。**第一次跑門檻是 56/56；加了「一律確認」規則後 C44 掉成 55/56**：程式把「from our earlier LIONESS co-expression run」裡的 LIONESS 算成點名的選項。修法是新增 `context_mentions`：讀取把只當背景提到的方法標出來，程式數名字時排除它們。C44 和 C58 的讀取因此各加了一行，已在 `judgment` 註明是第一次跑之後才補的。

## 第 1 階段要注意的讀取判斷

`gold_readings.yaml` 的 `judgment` 欄位，標出寫讀取時做的判斷，也就是模型最可能讀得不一樣的地方：

- C06：「across 60 samples」不算 scale。
- C12：資料類型從檔名讀出。
- C20：疑問讀成資料條件，而不是檔案疑問。
- C24：「不知道要哪種網路」讀成泛稱。
- C28：設計共變量不算分組。
- C44、C58：背景提到的方法。

- vague 被拒 ≤ 1；
