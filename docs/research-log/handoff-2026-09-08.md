## 問題 1（最高優先）證據契約使系統丟掉自己已正確萃取的語意

**兩個現象，同一個病灶。** 錯字那個是極端案例，普遍案例才是主要問題。

**現象 A（罕見，硬失敗）**：`"...mi-rna regualtor network, what toosl do i need?"`
→ `Semantic routing unavailable (ValueError)`。
證據 `.netzoo/sessions/af9f07e5.json`、`.netzoo/traces/79a16420-*/events.jsonl`。
**觸發條件很窄：要拼錯字。** `mi-rna` 小寫本身沒問題（`_normalized` 會收平大小寫與
連字號，`mi-rna` ≡ `mi-RNA`），兇手是 `regualtor` 這個字母顛倒。

**現象 B（8–12% 的試驗，安靜降級）**：拼字正確的同一題**也**產生了同樣兩個
`ungrounded_evidence`，但 review 的解法是**把欄位降級成 `unknown`**，不是補一個對得上的引文。
最終被接受的 outcome 是：

```
operation: "unknown"        ← 原本是 "infer"（正確），被移除
artifact_type: "unknown"    ← 原本是 "regulatory_network"（正確），被移除
regulator_types: ["mirna"]  ← 只剩這兩個真正被決定
granularity: "sample_specific"
```

答案仍然正確，**但只是因為這兩個欄位剛好足以指認 LIONESS-PUMA**。若問的是 TF，
同樣的降級會留下四個候選（實測見下）。

**歸因更正（2026-09-08，來自 35 輪 live 存檔重讀，未付費）**

上面「現象 B 的主因是 review 把欄位降級成 `unknown` 以消解 `ungrounded_evidence`」
**已被否證**。`scripts/analyze_unknown_downgrades.py` 把 **789 次試驗**中每一個
attempt-1 對不上原文的引文配到它在最終 outcome 的下場：
`no_accepted_outcome` **148**、`retained` 34、`replaced` 6、
**降級成 `unknown`：0**。

8–12% 這個數字本身無誤（7/57、5/60、6/60 已逐位重現），
但**那 18 次沒有一次在 attempt 1 有 `ungrounded_evidence`**；
它們的 issue 是 `missing_current_input` 與 `artifact_granularity`。
比率量在 `routing_scenarios.json`，機制觀察在
`routing_semantic_variants.json` 的 mi-rna 那題——**兩個不同的族群**。

同一批資料的第二點：`ungrounded_evidence` 的 span 是
**`absent` 185 對 `unmatched` 3**。`absent` ＝宣告 `explicit` 卻沒給任何 `text_span`，
且 79% 直接讓整輪解讀報廢。**1a 只能碰到那 3 筆；1b 目前值 0 筆。**

第三點：下面「把欄位設成 `unknown` 永遠可行且永遠會過」嚴格說不成立——
`request_integrity.py:104` 的 `terminal_goal_conflict` 已經是一個反例
（硬寫死，只涵蓋 `sample_cluster_assignment`）。若日後要做 1b，它是現成樣板。

**以下原文保留，作為當時的推論紀錄。**

**根本原因（兩層，第二層才是主因）**

1. **引文比對只有拼字軸的零容忍。** 明文證據的 `text_span` 必須出現在使用者原文
   （`outcome_validation.py:40 _grounded_span`，比對前經 `:32 _normalized`）。
   模型引用時把錯字改正 → 對不上 → `ungrounded_evidence`。
   事件裡 `span:"unmatched"`（非 `absent`）＝「引文有給、只是對不上」。
2. **`unknown` 免附證據，於是形成「丟棄語意」的結構性誘因。**
   `outcome_validation.py:89-113`：每個維度只在值 `!= "unknown"` 時才要求證據。
   所以引文對不上時，**把欄位設成 `unknown` 永遠可行且永遠會過**，而補一個合法引文
   既較難、在原文有錯字時甚至不可能。結果是系統丟掉自己已正確萃取的意義。
   離線量測（三輪 mini，同碼不同輪，穩定）：接受的 outcome 中
   `operation` 或 `artifact_type` 為 `unknown` 者 **r18 7/57、r19 5/60、r20 6/60（8–12%）**。
3. **`recoverable` 算了卻沒人讀。** `:235` 定義為「所有 issue 都是 `ungrounded_evidence`」
   ——現象 A、B 都符合。全庫 grep：**production 零處使用**，只有單元測試
   `test_evidence_validator_marks_translation_mismatch_as_recoverable` 斷言它。
4. **訊息指錯原因且建議保證無效。** `guidance_interaction.py:28-33` 說
   「routing **unavailable**」「**retry when available**」；實際上路由可用、跑了兩次付費呼叫
   （皆 `status: failed`），且錯字還在原文裡，**原封重試必然同樣失敗**。

**解法（依序；1a 與 1b 是不同軸，不要用單一相似度門檻一起解）**

- **1a 拼字軸容錯（不動內容軸）（已完成，Log 96／98）**：引文與原文做**詞對齊**——引文每個實詞都必須對齊到
  原文某詞、且該詞內編輯距離很小（短詞更嚴）；**引文不得有任何對齊不到的實詞**。
  拼字錯多少都收，內容多一個限定詞就拒。
  **不要**改成整句相似度門檻：`network`→`regulatory network` 的相似度不低於
  `regualtor`→`regulator`，單一門檻鬆到能救現象 A，就同時放行捏造。
- **1b 移除「降級成 unknown」的誘因**（**主因，效益最大**）：`ungrounded_evidence`
  不得靠把欄位改成 `unknown` 來消解——至少必須**記錄該降級並反映在 confidence**，
  使「我不知道」與「我知道但引文對不上」不再無法區分。
- **1c 接上 `recoverable`（已完成，Log 94／95；使用者已授權）**：剩下的（翻譯／改述）由「整個丟棄」降級為
  **接受解讀 + 證據標記未驗證 + 降低 confidence + 向使用者明說**。
  **會放寬安全性質，需使用者明確授權。**
- **1d 修訊息（僅 `unverified_evidence` 路徑已完成，其餘 fallback 訊息未動）**：如實說「解讀已完成，但引文無法對應原文」，停止建議「稍後重試」。
- **1e 讓它可量測（已完成，Log 90／91）**：語料 20 題分類只有 `positive/history/paraphrase/negative`，
  **全部拼字正確**（194 個詞經字典檢查，未拼錯者皆為屈折或領域詞），
  且**每題都明講自己有哪些輸入**——而真實使用者不會。新增兩類：
  拼字錯誤、以及**不陳述輸入的簡短提問**（現象 B 的真實觸發條件）。

**判準（放寬前先寫下，事後不改）**

- P1 現象 A 原句（含 `regualtor`／`toosl`）路由到 `LIONESS-PUMA`。
- P2 **負向控制必須仍被拒**：原文只說 `network`、引文寫 `regulatory network`
  （多一個原文沒有的限定詞）→ 仍判 `ungrounded_evidence`。**放寬的可否證性在此。**
- P3 現象 B：`operation`／`artifact_type` 為 `unknown` 的比率須自 8–12% 下降，
  且**下降不得來自把 `unknown` 改填成猜測值**——以 A 級（工具＋參數皆對）同步不下降為守門。
- P4 離線閘門不得有新失敗；既有 `_grounded_span` 相關測試全部保留。
- P5 新增語料類別後 digest 改變，**只能與同 digest 的輪次比較**。

## 附：路由不是寫死的關鍵字比對（已驗證，可重跑）

模型的輸出 schema **不含任何工作流程名稱**——`SemanticInterpretation` 只有
`request_mode`／`semantic_goal`／`outcome_hypotheses`，`RequestedOutcome` 只有 10 個
封閉詞彙欄位；`PANDA`／`PUMA`／`LIONESS`／`SAMBAR`／`CONDOR`／`OTTER`／`run_*`
在 schema 中**一次都沒出現**（僅描述文字寫著「Workflow-independent」「cannot select workflows」）。
選擇由 `match_semantic_request` 從**型別化欄位**對 registry 推導。
以 `user_task=""`（完全沒有文字可供任何關鍵字規則讀取）只改一個欄位：

| 欄位 | 選出 |
| --- | --- |
| `mirna` + `sample_specific` | `run_lioness_puma` |
| `mirna` + `aggregate` | `run_puma`, `run_lioness_puma` |
| `tf` + `sample_specific` | `run_lioness_panda` |
| `tf` + `aggregate` | `run_panda`, `run_lioness_panda`, `run_otter`, `run_giraffe` |
| regulator 未定 + `sample_specific` | 四個 sample-specific 全上 |

`mirna` 永不選到 PANDA、`tf` 永不選到 PUMA——是 registry 的 `regulator_types` 在作用。
**這也說明為何 1b 是主因**：欄位被降級成 `unknown` 時，候選集會從 1 個擴散到 4 個。

## 硬性禁令（最精簡；違反其中任一條都會產生假成果）

- **每次介入前先寫下可否證的判準，事後不改。** 放寬類的改動**必須**附負向控制
  （如 P2），否則「失敗消失了」與「理解正確了」無法區分。
- **不要把消除矛盾當成理解正確。** 一致性與正確性是兩件事。
- **容差必須來自方法作者自己的斷言**，不可自訂、不可加寬放係數。
- **對稱的 fixture 無法偵測方向性錯誤**（GIRAFFE 轉置缺陷因 2×2 fixture 存活）。
- **每個新測試都要驗證它在修正前會失敗**；通過原因錯的測試什麼都沒釘住。
- **單輪 n=14 無法排名版本**（噪音地板：gpt-4o 差 3 次試驗、mini 差 0）。
- **不要用 prompt 措辭當修正手段**（已六次失敗）；不要放寬 schema、吞 Pydantic error。
- **不要由程式填入模型沒寫的 outcome 欄位**（已授權例外僅 Log 28／32，且都不是填值）。
