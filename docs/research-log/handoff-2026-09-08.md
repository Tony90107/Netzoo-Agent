## 問題 1（最高優先）錯字使正確解讀被整個丟棄

**現象**：`"...sample specific mi-rna regualtor network, what toosl do i need?"`
→ `Semantic routing unavailable (ValueError)`；拼字正確的同一題正常答出 PUMA／LIONESS-PUMA。
證據：`.netzoo/sessions/af9f07e5.json`、`.netzoo/traces/79a16420-*/events.jsonl`。

**根本原因**（三層，缺一不可，要分開修）

1. **引文比對只有拼字軸的零容忍。** 明文證據的 `text_span` 必須出現在使用者原文中
   （`outcome_validation.py:40 _grounded_span`，比對前經 `:32 _normalized`）。
   模型理解正確（`regulatory_network` / `infer` / sample-specific 全對），但引用時
   **把錯字改正**成 `regulator network`，於是對不上 → `ungrounded_evidence`。
   事件記錄的 `span: "unmatched"`（非 `absent`）就是「引文有給、只是對不上」。
   注意大小寫與連字號**本來就會被正規化**（`mi-rna` ≡ `mi-RNA`），兇手是 `regualtor`。
2. **`recoverable` 算了卻沒人讀。** `outcome_validation.py:235` 定義為「所有 issue 都是
   `ungrounded_evidence`」——本案正是如此。全庫 grep：**production 零處使用**，
   只有一個單元測試 `test_evidence_validator_marks_translation_mismatch_as_recoverable`
   斷言它。設計意圖就是這一類（中文提問、模型引英文 "gene"）。
3. **訊息指錯原因且建議保證無效。** `guidance_interaction.py:28-33` 說
   「routing **unavailable**」「**retry when available**」。但路由可用、且跑了兩次付費呼叫
   （皆記為 `status: failed`）。錯字還在原文裡，**原封重試必然同樣失敗**。

**解法（依序，1 與 2 是不同軸，不要用單一相似度門檻一起解）**

- **1a 拼字軸容錯（不動內容軸）**：引文與原文做**詞對齊**——引文每個實詞都必須對齊到原文某詞
  且該詞內編輯距離很小（短詞更嚴）；**引文不得有任何對齊不到的實詞**。
  結果：拼字錯多少都收，內容多一個限定詞就拒。
  **不要**改成整句相似度門檻：`network`→`regulatory network` 的相似度不低於
  `regualtor`→`regulator`，單一門檻鬆到能救本案，就同時放行捏造。
- **2a 接上 `recoverable`**：剩下的（翻譯／改述）由「整個丟棄」降級為
  **接受解讀 + 證據標記未驗證 + 降低 confidence + 向使用者明說**。
  **這一項會放寬安全性質，需使用者明確授權。**
- **3a 修訊息**：如實說「解讀已完成，但引文無法對應原文」，停止建議「稍後重試」。
- **4a 讓它可量測**：語料現有分類只有 `positive/history/paraphrase/negative`，
  **20 題無任何拼字錯誤**，所以整個 benchmark 結構上看不到此模式。新增 typo 類別。

**判準（放寬前先寫下，事後不改）**

- P1 本案原句（含 `regualtor`／`toosl`）路由到 `LIONESS-PUMA`，且 `A` 級（工具＋參數皆對）。
- P2 **負向控制必須仍被拒**：原文只說 `network`、引文寫 `regulatory network`
  （多一個原文沒有的限定詞）→ 仍判 `ungrounded_evidence`。**這條是放寬的可否證性所在。**
- P3 離線閘門不得有新失敗；既有 `_grounded_span` 相關測試全部保留。
- P4 新增 typo 類別後語料 digest 改變，**只能與同 digest 的輪次比較**。

## 問題 2　12 個 capability 只核對 5 個，已核對的 5 個裡 2 個有缺陷

**根本原因**：先前只有路由層與結構層測試，**沒有執行層數值核對**；所以「路由正確、
欄位全過、契約全成立」與「數字是對的」被當成同一件事。已核對 5 個即抓到 2 個缺陷
（OTTER 安靜產出錯數字、GIRAFFE 完全跑不起來）→ **未核對的 7 個先驗要放低。**

**解法**：沿用 `tests/test_execution_numeric_reference.py` 的模式（本機 Docker、不付費）。
剩餘各項阻礙與做法：

| Capability | 阻礙 → 做法 |
| --- | --- |
| LIONESS ×3 | 參考檔由 class API 在 `modeProcess="legacy"`、`save_tmp=True`、`alpha=0.1` 下產生，我方走 CLI。**不是死路**：上游測試 1 有 `assert np.allclose` 比較 CLI 與 class → 據此逐項對齊 flag |
| PANDA / PUMA | 同上；且**上游自己的 CLI 測試只斷言 `returncode == 0`**，不比數值 → 需重建 class 預設並論證等價 |
| DRAGON | 上游無 `tests/dragon` 參考目錄 → 無第三方基準，只能做契約層 |
| BONOBO | 上游無測試資料亦無參考值 → 同上 |

**判準**：以**上游自己的斷言原樣呼叫**（COBRA/OTTER 用
`pd.testing.assert_frame_equal(rtol=1e-10, check_exact=False)`；GIRAFFE 用
`np.testing.assert_allclose(atol=1e-5)`），並驗證新測試在修正前會失敗。

## 問題 3　模型 27 次試驗中 24 次不提供判別維度

**根本原因**：多題在粗維度上相容多個 capability，真正分辨的是 role 或 registry tag；
而 **matcher 的決定性偏好會把缺口補上**，所以模型從未被迫產出那個資訊。
這 24 次在該量測存在前**全被評為完全正確**。

**與問題 1 同源**：都是「證據契約要求的東西，模型給不出來或形狀對不上」——
一邊是省略判別維度，一邊是引文正規化後對不上。修問題 1 時**不要順手放寬這條**。

**解法**：尚未決定。選項是（a）缺判別維度時不得回 `exact`，或（b）維持現狀但把
供給率當常設指標。**需使用者決定。**

## 硬性禁令（最精簡；違反其中任一條都會產生假成果）

- **每次介入前先寫下可否證的判準，事後不改。** 放寬類的改動**必須**附負向控制
  （如 P2），否則「失敗消失了」與「理解正確了」無法區分。
- **不要把消除矛盾當成理解正確。** 一致性與正確性是兩件事。
- **容差必須來自方法作者自己的斷言**，不可自訂、不可加寬放係數。
- **對稱的 fixture 無法偵測方向性錯誤**（GIRAFFE 轉置缺陷因 2×2 fixture 存活）。
- **每個新測試都要驗證它在修正前會失敗**；通過原因錯的測試什麼都沒釘住。
- **單輪 n=14 無法排名版本**（噪音地板：gpt-4o 差 3 次試驗、mini 差 0）。
- **不要用 prompt 措辭當修正手段**（已六次失敗）；不要放寬 schema、吞 Pydantic error。
- **不要由程式填入模型沒寫的 outcome 欄位**（已授權例外僅 Log 28／32，且都不是填值）。
- **付費呼叫**：gpt-4o-mini 已預先授權；**gpt-4o 每次都要先問**。
- 「上游測試全綠」是弱證據：`test_lioness.py` 有 8 處 `np.allclose` 沒有 `assert`。
