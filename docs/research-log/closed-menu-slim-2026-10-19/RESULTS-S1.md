spec：`docs/superpowers/specs/2026-10-19-slim-reading-fields-design.md`（46a35b05）。本階段沒有呼叫模型。

## 結論

- **新形狀能裝下判定需要的一切**：第 0 階段 56 題金標轉成精簡形狀再轉回，判定與原本完全相同，55/56。
- **只讀程式選出的 B 類欄位也一樣是 55/56**：把金標拆成「第 1 步會讀的部分」加上「第 2 步選中的 B 類欄位」，判定不變。程式沒有漏選任何會影響判定的 B 類欄位。
- **唯一沒過的是 C35**，原因是 S1 新加的 B4 規則，不是新形狀（見下方「待決定 1」）。
- **每題寫出的值大幅減少**：同樣的內容，舊形狀第一次讀取中位數 208 個值，精簡形狀兩步加起來中位數 35 個；有內容的值從 25 個降到 15.5 個。這是離線估計，實際數字要 S2 量。
- **第 3 步不一定要跑**：金標 56 題裡有 35 題需要第 3 步，每題 1–3 格。
- **B2 的觸發條件需要你決定**（見「待決定 2」）：照 spec 表格字面寫，金標會掉到 53/56。

## 實作內容

| 檔案 | 內容 |
|---|---|
| `contracts/slim_reading.py` | `SlimReading`：A1 每個要求一筆、A2 名稱角色、A3 有／沒有＋「只有這些」、A4 執行或詢問，以及「提到的事實」清單（B、C、D 類，每筆含欄位、值、原文；不確定時列出在哪幾個值之間） |
| `interpretation/slim_reader.py` | 第 1 步 schema（`core_model`）與選單文字（`core_text`）、`from_core`；第 2 步 `slim_needs`；第 3 步 schema（`focus_model`）、`focus_text`、`merge_focus`；與判定表互轉（`to_menu`、`to_slim`）；計數（`wire_payloads`、`wire_values`） |
| `interpretation/menu_decision.py` | `b_fields`：依候選 workflow 的合約選出第 3 步要讀的 B1–B4 欄位；B4 的共用部分抽成 `_b4_open` |
| `graph/slim_reading_call.py` | `read_slim`：第 1 步呼叫 → 程式選欄位 → 有需要才呼叫第 3 步。讀取失敗是 UNCHECKED；第 3 步失敗就保留第 1 步，B 類欄位沒讀到，只會追問 |
| `tests/test_slim_reading.py` | 18 個測試，含新欄位的齊全性檢查 C1–C4（見下） |

- **兩個 schema 的大小**：
  - 第 1 步的選單文字 6.2k 字元，v8 是 13.8k。只列結果、workflow、資料種類、事實欄位，不列任何 B 類欄位或 control。
  - 第 1 步全是清單，沒提到的不寫。
  - 第 3 步每個選中的欄位一格（說了／不確定／沒說），加上 B5 設定清單與 B6 數量清單。
- **程式負責的事**：
  - 逐字核對每段原文；
  - 對照每個欄位的選單檢查值；
  - 「只有這些」需要原文；
  - 檔名或欄位名不算清單外的結果，也不算設定；
  - 各層的特徵數由程式相加。
- **欄位合併**（spec 3 的合併表）：
  - B2 一格同時給出調控因子和 miRNA 由什麼驅動；
  - B3 一格給出整合方式和層數；
  - value_type 是唯一被兩個欄位讀的值：二元值在第 1 步以 C4 讀，DRAGON 的連續值在第 3 步以 B4 讀。只在第 1 步沒讀到時才會在第 3 步讀，所以仍是只讀一次。

### 第 2 步怎麼選 B 類欄位

| 欄位 | 什麼時候讀 |
|---|---|
| B1 規模 | 不同規模（含清單外的值）會導向不同判定。「每組一個」只在使用者提到分組時出現 |
| B2 調控因子 | 同上：只要有調控類結果在候選中就會讀（見待決定 2） |
| B3 多層 | 候選中有 workflow 給出多組學聯合結果時（spec 的條件）。照「會不會改變判定」來選會選太多：任何請求說「joint」都會被拒，所以 SAMBAR 的題也會被選上 |
| B4 | 候選 workflow 在 `b4_conditions` 列出的條件還沒說，而且不同值會導向不同判定 |
| B5 | 第 3 步有跑就讀：只列候選的 control。BONOBO 由 B4 讀的兩個設定不重複列出 |
| B6 | 候選有數量限制時才讀 |

第 1 步判定已經是 CLARIFY、DECLINE 或 UNCHECKED，或候選超過 6 個時，第 3 步不跑。這時結果還沒定，B 類等使用者選了結果再讀。

## 每題寫出的值（`s1_values.py`，結果在 `s1-values.json`）

計數方式和第 1 步分析相同：每個葉節點算一個，空清單算一個；「有內容」是非空、非 null、非 false、非「沒說」。用這個數法重算第 1 階段，得到中位數 207.5 和 25，和 spec 第 0 節的 208／26 一致。

| | 舊：第一次讀取 | 舊：加聚焦重讀 | 精簡：第 1 步 | 精簡：兩步合計 |
|---|---|---|---|---|
| bench p1（112 次讀取）寫出 | 207.5（最多 386） | 244（452） | 19（35） | **35（87）** |
| bench p1 有內容 | 25 | 36 | 9 | 15.5 |
| dev d9（85 次讀取）寫出 | 192（445） | 230（483） | 16（31） | **26（59）** |
| dev d9 有內容 | 19 | 26 | 6 | 10 |
| 金標 56 題（精簡形狀）寫出 | — | — | 18.5（31） | **30.5（63）** |

- 精簡的數字是**估計**：把已記錄的讀取內容改寫成精簡形狀，看會寫出多少。
- 估計值大致落在 spec 的目標「每題約 15–30 個」，略高一點。
- 模型實際會寫多少、會不會多寫，要在 S2 實測。

## 待決定（需要你同意才會寫進 spec 變更紀錄）

1. **C35（SAMBAR，「248 endometrial tumours … non-negative mutation counts」）**：
   - 現況：
     - B4 規則照字面執行：沒說體細胞或生殖細胞，就問；
     - 金標是在 B4 規則之前寫的，沒有標體細胞，所以這題變成多問一題（needless_question）。
   - spec 的 B 類允許「可推斷」：腫瘤的突變數可以讀成體細胞。實際讀取時由第 3 步的模型判斷，我沒有改金標，金標不能拿判定表去調。
   - 兩個選項：
     - (a) 維持字面，S2、S3 照實記錄這類多問；
     - (b) 在 spec 寫明「腫瘤樣本的突變資料視為體細胞」。這是新的推斷規則，需要你決定。
2. **B2 的觸發條件**：
   - spec 表格寫的是「PUMA 類與 PANDA 類都還是候選」才讀。照字面實作，金標有 2 題會錯：
     - C06：RNA-binding protein 加 TF，只剩 PANDA 類候選，沒讀到清單外的調控因子，變成去問規模；
     - C59：提到 miRNA，但 B2 沒讀，多問一次調控因子。
   - 目前的實作：只要候選有調控類結果，就在第 3 步讀 B2。
   - B2「沒說」時仍然照附加項規則當成只有 TF，不會多問使用者。所以放寬的只是「讀」，不是「問」。
   - 建議採用目前的實作，並在 spec 變更紀錄補一句。你同意才寫進去。
