# Fact labelling brief (blind): is each written value what the request says?

File to label: live/s2b/facts-to-label.json (in this folder). For each item: the user's request (`prompt`) and the values a reader wrote (`facts`: `what` = field and value, `quote` = the words it cites).
For every fact give one label:
- `supported`: the request's words state this value, outright or by words as clear as saying it (the quote may be loose; judge the whole request).
- `wrong_value`: the request speaks to this field but says a different value (e.g. the user is unsure and the fact says stated, or per sample where the user asked for one network).
- `not_supported`: the request does not speak to this field at all; the value was filled in without words saying it.
Judge only what the words say, never whether NetZoo can do it. Unsure facts are supported only if the user really is unsure between those values.

## Field meanings
- A1 item: what one thing the request asks says. menu_result = a result on the menu named (or asked about); kind_of_result = only a generic word (network, regulation); workflow_only = a workflow or a run named, no result; method_choice = choosing between methods, no result; purpose_or_topic = no result, only a purpose, topic or question; off_menu_result = a result no workflow gives; unsure_between_results = the user does not know which of the listed results.
- Results on the menu: regulatory_network: A weighted regulator-to-gene network (TF, or TF and miRNA).; targeting_scores: Each regulator's out-degree or each gene's in-degree in a regulatory network.; tf_activity: Each TF's activity in each sample, estimated apart from its own mRNA level.; coexpression_network: An undirected gene-gene co-expression network.; covariate_adjustment: Co-expression split by, or adjusted for, covariates in a design matrix (and a network built from it).; multi_omic_network: An undirected partial-correlation network within and between two matched omics layers.; edge_significance: A p-value per edge, to filter a network by significance.; communities: Communities in a regulator-gene network, with memberships and each node's core score.; community_enrichment: Pathway enrichment of each community's genes.; patient_subtypes: Patient subtypes from somatic mutations, with gene and pathway mutation scores.
- A3 data <kind>: has / lacks = the user says they have / do not have it. Kinds: expression: a gene expression table (RNA-seq counts, microarray, normalised expression); coexpression_matrix: a gene-by-gene co-expression or correlation matrix; motif_prior: a TF-to-gene motif prior; ppi: a protein-protein (TF-TF) interaction network; mirna_prior: a miRNA-to-target-gene prior; mutation_calls: mutation calls or counts per gene and patient; design_matrix: a sample sheet or design matrix of covariates; regulator_gene_network: an existing regulator-to-gene network; methylation: a methylation layer; protein: a protein (proteomics) layer; metabolite: a metabolite (metabolomics) layer; mirna_expression: measured miRNA expression; chromatin: a chromatin layer (ATAC-seq, ChIP-seq); other_omics: another omics layer (copy number, lipids, microbiome)
- A3 these are all the data = the user says the listed data are all they have. A4 = the user asks to run it now.
- B1 granularity: whole_cohort (one result for all samples), per_group (one per group), per_sample (one per sample). 'A network' alone states no scale.
- B2 regulators: tf (TFs only), tf_mirna (TFs and miRNAs from a target prior), off_menu (lncRNAs, RBPs, other regulators). B2 mirna_driver: measured_expression (miRNA links driven by measured miRNA expression) or target_prior.
- B3 integration: joint (one model linking two layers) / per_layer. B3 layers: three_or_more_jointly (three or more layers that must be in one model).
- B4 mutation_origin: Whether the mutations to be scored are acquired somatic mutations or inherited germline variants.; samples_matched: Whether the user's different omics data types were measured on the same samples.; value_type: Whether the omics measurements to be modeled are continuous values or binary indicators.; input_network: What an existing network the user gives holds: regulator-to-gene edges or gene-gene edges. B4 setting:log_transformed / setting:centered (BONOBO) = whether the user's data are declared log-transformed / centered.
- B5 <control> = a setting the user asks to run with (unregistered = a setting no control takes). Words that only describe data or where results go are no setting.
- B6 sample_count / feature_count / single_feature_count = a number of samples / features the user gives.
- C2 claims: causal (proof of causation) or prediction (a trained predictive model). C3 delivery outside_netzoo: sending, uploading, a dashboard, a schedule.
- C4 conditions: data_unit single_cells; value_type binary; time_model dynamic (a model of change from one time point to the next); spatial uses_neighbors; group_membership several_groups (overlapping groups).
- D1 groups = groups or conditions among the samples. D2 compare: later (a comparison the user will do afterwards), describe, test. D3 signed: signed (activation vs repression) / unsigned. D4 requirements = a requirement on how the result is computed or what it contains. D5 data_stage raw_files = FASTQ/BAM/peak files. D6 unsure_files = a doubt about what a named file holds.
- C5 unregistered method = a method or variant the user asks to use that NetZoo does not register.

Output: live/s2b/fact-labels.json = a JSON list [{"id": ..., "labels": [{"n": 1, "what": "<copy>", "label": "supported|wrong_value|not_supported", "why": "<= 12 words"}, ...]}, ...] with every item and every fact.
