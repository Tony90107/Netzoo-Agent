# ROUND-26 第 0 階段：逐欄位金標與現行讀題的對應正確率（2026-10-22）

- 計畫：`collab/ROUND-26-PLAN.md` 1.2、3.3(1)
- 程式：`77c339a3`
- 費用：沒有呼叫模型。標註由 subagent 完成，不花 API 費用。

## 金標

- **標註者：** 300 題（核心 60 題，h1–h5 各 48 題），由 6 個盲標的 subagent 標註。它們只看請求原文、`vocabulary.md` 與 13 個 YAML，看不到代理的讀取結果，也看不到題目的四類金標。
- **規模：**

| 欄位 | 數量 |
|---|---|
| 結果 | 281 |
| 設定 | 245 |
| 使用者有的資料 | 687 |
| 使用者說沒有的資料 | 16 |
| 資料來源 | 146 |

- **抽查：** 31 題（10%），全部可以接受，沒有發現標錯。
- **計分規則：** 抽查時發現各批標註習慣不同（`SPOT-CHECK.md`），所以計分時分開報告以下幾類：
  - 只點名方法的結果；
  - 可接受集合超過 3 個 id 的結果；
  - 宣告資料性質的設定（log_transformed 等）。
  - 正確率依題組分開報告，不合併。

## 觀察

1. **錯誤以「漏」為主，不是「對錯」。**
   - 設定：漏 98、錯 31；
   - 結果：漏 117、錯 12。
   - 提案二要解決的不只是「選錯」，更多是「沒選」。候選並排之外，觸發條件（哪些話要對應）同樣重要，例如逐字出現的設定名稱、沒讀到的數字。
2. **h5 上的錯誤，逐段來看與先前的診斷一致：**

| 題目 | 讀題結果 |
|---|---|
| Q42 | 「keep the full matrices …」讀成 `keep_in_memory`，或沒對到 sparsify |
| Q09 | 「sparsify switched on」漏讀 |
| Q10 | signed regulation 漏讀 |
| Q26 | kmin、kmax 漏讀 |

3. **新發現：Q38。** 使用者在 GIRAFFE 的請求中說「learning rate」「iterations」，讀題卻對到 OTTER 的 eta 與 iterations；金標是「未登錄」，因為 GIRAFFE 沒有任何設定。這正是提案二 a 的設計原則：候選只限於點名或被 credit 的 workflow。
4. **h5 的設定正確率（55%）明顯低於其他題組。** 這和 h5 在 live 中的表現較差一致。但 h5 的設定單位只有 31 個，需要更多單位才能下結論。
