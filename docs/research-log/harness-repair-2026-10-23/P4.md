# Harness repair P4: input and long-term memory freshness (2026-10-23)

Implemented to the design and gates in [ROUND-P4.md](ROUND-P4.md), which did not change. Code changes only, no model calls, cost **$0**.

| `data/artifact_revision.py` (new) | `revision` and `step_revisions` (sha256 streamed in 1 MiB chunks), `input_files` (the step's required inputs plus optional input files; outputs excluded), and `freshness` (`unchanged` / `changed` / `rules_changed` / `missing` / `unverified`, with what differs in words). If a file cannot be read, the run is refused only when there is a preview to compare against. The comparison lives in `data/`, so `graph/execution.py` stays within its 230-line limit (223 lines). |

| `memory/episodes.py`, `graph/policy_memory.py` | `EpisodeStore.record(..., input_revisions=)` maps the execute gate's fingerprints to fields by canonical path. Retention, capacity, deletion, private storage and lock behaviour are unchanged; the new field lives in the same file. |

### Hash cost (measured)

- Project data `data/sambar-official-toy/mut.ucec.csv` (10.0 MB): **6.8 ms** per hash, about 1.5 GB/s (warm cache).
- A 500 MB synthetic file: **0.34 s**, the same rate. Without the cache, the disk's read speed is the limit.
- `validator_hash` (the `data/` source code): 7.9 ms, once per process.
- Extra I/O: each dry-run preview and each execution hashes that step's input files once (a confirmed run is twice). Episode reuse hashes each reused file once per planning turn (only when `reuse_last_inputs` is on). The input checks read these files in full already, so the extra cost is of the same order.

## Limits

- **TOCTOU only shrinks to the gate.** Subprocess workflows (PANDA, LIONESS, CONDOR, COBRA, SAMBAR …) re-open the paths after the gate, and nothing is copied; a change after the gate cannot be seen. In-process workflows (OTTER, DRAGON) also load again after their own checks.
- **The check-code fingerprint is coarse.** Any change in `data/*.py` makes every earlier check `rules_changed`, which is conservative. Changes in helpers outside `data/` that a check calls (`workflow_registry`, `interpretation/giraffe_demo` …) are not seen. `policy_hash` is global: any YAML or AGENTS.md change counts as `rules_changed`.
- **Freshness does not change reuse selection.** A changed file is still offered (validated again at planning time; confirmation needed); only the reason is more accurate.
- **A resumed `needs_confirmation` plan is not compared with what was shown before.** It is re-planned and checked at confirmation time.
- **When a run is refused after a preview, the episode is still recorded as `failed`.** This follows the existing refusal path. Failed episodes are never reused.
- **No typed parameter snapshot** (`parameters` stays a name list).
- **A preview that could not read a file has no fingerprints.** A dry-run preview always passes through `execute_tool`, but if a file was unreadable at that moment the preview records nothing, and the confirmed run compares nothing either, as before. An unreadable file usually fails the input checks first.
