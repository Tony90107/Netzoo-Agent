## 改了什麼

### 1. DO + partial（`interpretation/same_run.py`、`method_conditions.py`）

- 同一 run 的設定不支援時，只有在兩個條件都成立時才不擋：
  - workflow 仍可用自己的設定執行，也就是在 `defaults` 裡、沒有資料量問題；
  - 有一列可做的列，原文用 workflow 的註冊名稱點名了它。

  這時判定為 DO + partial，`partial_gap` 不是核准 run 的 verdict，所以 run 自動暫停，等使用者確認。
- `settings_apart` 拆出來的設定列，現在把仍可執行的 workflow 填進 `defaults`，和 M1 的語意一致。回覆因此多出一句「W itself can still run, with its own settings instead」，內容屬實。
- 照舊擋下的情況：
  - run 限制（樣本數、資料量，例如 L13）；
  - 可做的列沒有點名 workflow（H18、C08），因為那一列是附帶的問句或目的句。
- 第一版只看 `defaults`，結果 H18 和 C08 ×4 也被放行，把問句列成可做。改成要求「點名」後，只剩重標的三題（加上無金標的 MX18）改變。

### 2. 兩層理由（新增 `interpretation/reason_layers.py`）

- **第一層**沿用 ROUND-20 能由程式核實的理由（`stated_reasons`）。
- **第二層**用在沒有第一層理由的列。它只說查了什麼，不說為什麼做不到，全部由程式組成：
  - 「I couldn't match this to anything a registered NetZoo workflow produces or lets you set.」；
  - 該列原文點名的 workflow 產出什麼；
  - 每則回覆一次，列出接受這類資料的已註冊 workflow，並請使用者指出是否其實指其中一個。

  第一版寫的是「can run」。但 PANDA 還需要 motif／PPI prior，使用者不一定有，所以改成「take the kind of data you described」。
- **「no registered workflow produces this」只留在有 registry-wide 理由時。** 只有 near miss 的列，開頭改成「I couldn't match this to a result any registered NetZoo workflow produces.」，後面仍附 near miss。
- **改寫的位置**：
  - `_status_line`、`unavailable_rows`、`full_gap_reply` 的結尾；
  - partial 列的「no registered workflow produces the rest」；
  - `core_views.decline_reply`；
  - 缺口卡片的標題。

### 3. 空 matching

在回覆層處理：沒對到時說「我對不到」，不再說「沒有任何 workflow 能產出」（第 2 項）。判定種類（kind）沒有改，理由如下：

- replay 裡完全沒對到、也沒附理由的 DECLINE 共 45 份，金標是 CLARIFY 24、DECLINE 19、ASK 1、DO 1。改判 CLARIFY 會修好 24 份、弄壞 19 份，違反 BREAK 0。
- 這就是 10-17 在 held-out ha1 上失敗過的規則 A。
- spec 也規定沒有任何候選時維持 DECLINE（相容既有金標）。
- 「有候選而未建立支持」在 replay 中分不出來：路由候選（`check.cleared`）只在 live 設定，replay 沒有。

## 仍然不支援的地方

- **MX12 這類情況。** 結果列（signed R、sample-varying TFA）的原文沒有寫出 workflow，程式分不出它們和 C08 的目的句，所以照 ROUND-17 擋下。這和 91a8c2d9 相同，但不是 partial 決定所希望的結果。
- **背景片語被讀成需求（A06／A07）**沒處理。H40 的背景片語現在顯示為「available from GIRAFFE」，內容屬實，但不是使用者要的東西。
- **near miss 的綁定無法由程式核實**，C07 ×2 仍說錯。
- **空 matching 在判定層沒有改。** 如上所述，需要 live 的路由候選，或讀取層的改動。
- **第二層的資料類型來自模型的讀取。** 若讀錯，列出的 workflow 會跟著錯；不過那句話陳述的是 registry 事實，並請使用者確認。
