- **同一件事的判準**：不同來源之間，使用者原文重疊，且 workflow 有交集。count 只看原文，沿用 phase 5b 的既有規則。agent 自己的兩題不互相涵蓋，詳見下面「過程中修正的錯誤」。
- **移除**：`graph/fact_check_call.py` 的 `without_legacy_waits`、`waits_after_agent`，以及 `core_decision.agent_questions`。`apply_fact_check` 不再改動 check。
- **相容**：`FactQuestion.fact_key`、`FactCheck.queued` 是新增欄位，所以 `TaskDecision` 的 schema 雜湊更新了。已驗證只拿掉這兩欄時，雜湊會回到原值。研究工具 `replay_full.py` 與 `reading-coverage-2026-10-20/replay.py` 能辨認新程式：新程式不解除，舊 checkout 照舊解除。

## 過程中修正的錯誤

第一版讓所有來源都能互相涵蓋。逐題比對後發現，5 個回合少問了一題，其中 2 個漏掉的正是關鍵問題：

- Q17 h5：agent 問了「mean-centered per gene?」和「log-transformed before centering?」，兩題原文重疊，第二題被當成已涵蓋。
- L07 h3：同樣的情況。

agent 本來就會在重疊的原文上提出不同的事實，而 `kept_facts` 的 R6 已經去掉原文完全相同的重複題。所以改成只有不同來源之間才能互相涵蓋；修正後沒有任何回合少問。

## 仍然不支援的地方

- **綁定只看原文與 workflow，不看語意。** 33 種「舊問題 ↔ agent 問題」組合中，3 種問的是另一件事：
  - C56 p3：somatic 的問題被綁到「四個檔案的基因是否重疊」；
  - C44 p5r：scale 的問題被綁到「coexp_liver.tsv 是哪種表」；
  - C06 p3：TF 或 RBP 的選擇被綁到「有沒有 TF 清單」。

  這些舊問題在 91a8c2d9 上同樣不會被問（當時整批解除），所以不是退步，但 ledger 的 `asked_as` 只代表符合綁定條件，不代表問的是同一件事。C56 p3 的判定雖然變對（ASK），問的卻不是關鍵事實。要分辨這種情況，需要讓 agent 的問題帶上有型別的事實，這屬於讀取層的改動，不在 P1 範圍內。
- **live 的路徑差異 replay 量不到。** agent 有提問且仍有舊問題時，router 現在走等待路徑：不算 run verdict，也不做 goal read。replay 沿用錄製的 run verdict，所以這類 run 回合在 live 中可能從 UNCHECKED 變成 ASK，replay 看不到。
- **其餘未處理項目：**
  - 排隊的問題只記錄在本回合，跨回合保存屬於 P3。
  - agent 沒提問時，舊路徑仍會一次問完所有待問條件，沒有兩題上限。
  - spec 的 FactRecord 與 RuleEvaluation 留到 P2／P3，需要時才建。
