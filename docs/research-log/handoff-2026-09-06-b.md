## 二、已確認的成果（有「預測→驗證」支持）

1. **review 改為欄位範圍的 patch**（Log 32、35–38）。第二次語意呼叫要求
   `SemanticPatch`，只回傳要改的欄位；沒提到的欄位由程式沿用第一次的值。
   **沒有發明任何值**（沿用的是第一次模型自己寫的，改動的是 review 自己寫的），
   合併結果走**完全相同**的 strict validation，呼叫次數與 token 上限不變。
   判準在花錢前寫入 Log 37 並由 `scripts/compare_repair_rounds.py` 執行。
2. **CONDOR 可達性**（Log 31、40）。`community_assignment` 宣告
   `granularities={aggregate}`。原本 CONDOR 只能由 `granularity=not_applicable` 選到，
   而 semantic prompt 保留該值給「完全沒有科學結果」的請求——
   **模型能產生的解讀與能選到 CONDOR 的解讀交集為空**。預測在 r3 精確成立。
3. **等價巢狀的 evidence 清單**（Log 39、40）。模型把 root 的 `evidence_additions`
   放進 `outcome` 內，5/5 全失敗；比照 `SemanticReview._normalize_hypothesis_metadata`
   的既有先例接受，衝突時 raise。預測成立（5→0，patch 佔比 67%→100%）。
4. **fallback 不採用只出現在歷史子句的工作流程名稱**（Log 41、43）。
   r3 曾對一個明文說「不要推論網路」的負向控制推薦 forbidden 的 PANDA，
   來源是「Previously I used PANDA」。三項預測全部成立，並連帶讓
   `mirna-current-goal` 由 `run_panda` 回到正確的 `run_lioness_puma`。
5. **ambiguous 可攜帶全部候選**（Log 42）。`hypothesis_actions` 上限寫死 6 而
   capability 有 12 個，**完全未解析的 outcome 與全部 12 個部分相容**，
   曾讓一整輪全語料當機且報告全失。界限改由 registry 推導。

上一段研究的兩項成果（Log 25／26 的證據豁免）**仍然有效且必須保留**：
ontology 唯一決定的維度、以及 request witnesses 已確認的輸入，不另外要求證據。
**任何寫成「改了核心欄位就必須有 evidence 條目」的規則都會推翻它們**，
正確措辭是「沒有通過**驗證器所要求的**證據」。

## 四、我在本段犯的方法論錯誤（務必避免重蹈）

1. **宣告了一個在可行樣本量下無法判別的判準**（見上表第一列）。
   宣告判準時要先估基準率與樣本量，否則「未下降」與「測不到」無法區分。
2. **量測工具自己漏算。** `compare_repair_rounds.py` 原本排除帶 `error_type` 的紀錄，
   而 schema 失敗**只**記在那裡——等於把它唯一要量的類別過濾掉。
   **工具要先對著已知資料驗證過再用。**
3. **由個案過度概化。** 把「改了欄位沒附證據」稱為「三輪一致的主要機制」，
   報表出來後是次要項。**個案共同的形狀不等於統計主導項。**
4. **提出介入前沒有先量。** 我曾建議擴充 input witnesses，量了以後發現方向相反。
