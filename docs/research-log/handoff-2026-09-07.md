## 四、本段新增的方法論禁令（務必避免重蹈；我在本段都犯過）

1. **容差必須來自方法作者自己的斷言，不可自訂。**
   我第一版自己寫純相對誤差函式，還加 `*10`、`*1e4` 寬放係數。它在 COBRA 最後一個
   特徵值上失敗——400 樣本對 4000 基因，共變異數矩陣秩不足，該特徵值精確算術下為 0、
   浮點下是雜訊，對 0 取相對誤差**沒有定義**。上游用
   `pd.testing.assert_frame_equal(..., rtol=1e-10, check_exact=False)`，
   而 pandas 會**同時**套用預設 `atol=1e-8`——那個 atol 才是吸收雜訊的東西。
   **原樣呼叫上游那一行**即全數通過。寬放係數只是在掩蓋自己選錯工具。
2. **對稱的 fixture 無法偵測方向性錯誤。** GIRAFFE 的轉置缺陷之所以存活，是因為唯一的
   mock 測試 fixture 用 2 gene × 2 TF——**方陣看不出轉置**，那個 mock 還斷言
   `prior.shape == (2, 2)`，兩種方向都成立。**寫方向性測試時 fixture 必須非方陣。**
3. **每個新測試都要驗證它在修正前會失敗。** 本段照做並因此發現：OTTER 新增的 3 個
   離線測試**只有 1 個真的咬到缺陷**，另兩個在舊碼下也通過（「全部指派 1.0」本身就是
   二值且與順序無關）——它們是性質守衛而非迴歸測試，我在 commit 訊息裡如實區分。
   我也曾寫出一個只斷言「二值化是二值的」和「import 不是 None」的假測試，發現後改掉。
4. **不要混用不同比較的數字。** 我的 docstring 原寫「436,260 格與獨立二值化不符」——
   那是與**加權** P 的差異數；與二值化的差異是 350,312。**這個數字本來會進論文。**
5. **不要把限制寫得比實際查核更強。** 我在論文文件寫「PANDA/PUMA 完全無法與上游比較」，
   實際上 `run_panda` 有兩條路徑，非 precomputed 那條就是 `netzoopy panda`，
   不要求 `--coexpression`。已改為第一節的說法。
6. **「上游測試全綠」是比看起來更弱的證據。** netZooPy 的 `test_lioness.py` 有
   **8 處 `np.allclose(...)` 沒有 `assert`**（第 72、73、77、78、79、90、99、108 行），
   算完布林值就丟棄，那些行無論數值如何都通過；同檔另有 3 處是真的 `assert`。
   **引用上游斷言時只用真的有斷言的那些。**
7. **設定 `EXECUTE_TOOLS` 要用 `configure_runtime(EXECUTE_TOOLS=True)`。**
   `command.py` 是 `from .settings import EXECUTE_TOOLS` 取值綁定，直接設
   `settings.EXECUTE_TOOLS` 只對動態讀取 `settings.X` 的路徑有效（OTTER／GIRAFFE），
   對走 CLI 的路徑（SAMBAR／COBRA／CONDOR／PANDA／PUMA／LIONESS）無效。
   `runtime.set_runtime_value` 會走遍 `sys.modules` 在每個持有該名稱的模組上重新賦值。
   **這不是缺陷，是我一度用錯開關。**

## 五、已確認的成果（不要重做，也不要用別的數字取代）

**本段修掉的三個缺陷**（各附迴歸測試，均驗證過修正前會失敗）：

1. **OTTER PPI 投影（最危險：安靜產出錯數字）**——`data/otter.py` 的邊表讀取器
   **要求**權重欄、驗證它是數值、然後**丟掉它**，對每條列出的邊一律指派 1.0。
   丟棄信賴度是 yaml 有記載的選擇；但 **weight 0 被指派成 1.0 在任何解讀下都是錯的**。
   實測上游 toy data（661 TF）：436,260 個非對角格中 350,312 個本應為 0、85,948 個本應為正
   → **80.3% 的網路被憑空造成「有互作」**，稀疏網路變全連通，結果網路差 1.5e-5
   （值本身約 7.4e-6，同數量級）。**路由正確、欄位全通過驗證、結構契約全成立、
   輸出形狀與識別碼都對——只有數字錯，毫無警告。**
2. **GIRAFFE prior 方向（該 capability 從來跑不起來）**——netZooPy 要求 prior 為 gene×TF
   （上游寫 `Giraffe(expression, motif.T, ppi)`），我方傳 TF×gene 且未轉置
   → 只要 gene 數 ≠ TF 數必定失敗，即永遠失敗。`EXECUTE_TOOLS` 預設 False，
   沒有任何測試真的執行過它。
3. **GIRAFFE PPI 格式不可達**——dense 判定同時要求「首格是 ID token」（意味有標頭列）
   與 `shape[0] == shape[1] - 1`（意味無標頭列），**兩者不可能同時成立**
   → 有記載的標記方陣格式全被拒收；反而 2 列的三欄邊表（2×3）被**誤判成方陣**。

**嚴重性分級（不可混為一談）**：OTTER 是**錯數字、無警告**；兩個 GIRAFFE 缺陷是
**fail-safe**（使用者拿到錯誤訊息，不是錯誤結果）。論文文件 §5.6 依此排序。

**沿用上一段、仍然有效的數字**（不要用別的取代）：
- 受控 A/B（注入相同第一次提案）：`passed` **0/33 → 16/33**，+48.5 pp，p = 3e-6
- 模型效應：**A 19.0% → 42.9%**，p = 0.033（原始工具正確率分不開，複合指標分得開）
- **噪音地板**：同碼複製，gpt-4o 工具正確率差 **3 次試驗**、mini 差 **0**；
  **單輪 n=14 無法排名版本**
- 語料：**20 題**，其中 **9 題**標註 `required_discriminators`
- Log 25／26 的證據豁免**仍須保留**：ontology 唯一決定的維度、
