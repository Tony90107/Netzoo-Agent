# ROUND-23 量測：用 R21-A 的目標窄讀交叉檢查「請說清楚」的界線——不採用

- 日期：2026-10-21
- 起點：`e2fb5a63`（已推送）
- 費用：**US$0.0085**（gpt-4o-mini，113 個請求各一次）
- 沒有改產品程式。

## 動機

現行讀題形狀的回合，剩下的錯誤中最大的一群在「請說清楚」的界線上：
- `goal_unclear` 判錯 11 次：金標問一題 6、能做 3、不能做 2；
- 金標請說清楚，卻給了結果 7 次（`results_given`，例如 C53「how genes are connected」）。

R21-A 的目標窄讀（「請求有沒有指名要什麼結果」）在 full gap 上分得很乾淨（30/30）。所以我測了它能不能雙向交叉檢查：兩種不同形狀的讀法意見不同時才改判（ExtractConf）。

## 結果（`size.py`、`reads.json`）

| 路徑 | 金標 | 窄讀：有指名 | 窄讀：沒指名 |
|---|---|---|---|
| goal_unclear（判請說清楚） | 請說清楚 95 | 0 | **95** |
| | 問一題 6 | 1 | 5 |
| | 能做 3 | 2 | 1 |
| | 不能做 2 | 0 | 2 |
| results_given（給了結果） | 能做 80 | **74** | **6** |
| | 請說清楚 7 | 0 | 7 |
| | 問一題 3 | 1 | 2 |
| | 不能做 1 | 1 | 0 |

- **方向一**（目標不清楚、但窄讀說有指名 → 不判請說清楚）：只動到 3 份（問一題 1、能做 2）。金標問一題的那份還需要 fact agent 才會判對，但 `goal_unclear` 時 fact agent 根本沒有跑。
- **方向二**（給了結果、但窄讀說沒指名 → 改判請說清楚）：修好 7、改壞 6，**淨 +1**。
- **改壞的 6 份是：**
  - 點名 workflow 的執行請求（「Start COBRA right away…」「Launch LIONESS-DRAGON with…」「Run CONDOR now on…」），窄讀把「跑某個方法」當成沒指名結果；
  - 窄讀讀錯：M24、J43「estimate how active each transcription factor is in each tumour」其實指名了結果（TF activity）。

## 結論

- 窄讀在 full gap 上很準，是因為那裡的對照組都是「點名表外結果」。到了能做的回合，執行請求與能力問題很多，它的精確度不夠當交叉檢查。
- 不實作。
